Proyectos open source e implementaciones de referencia, con arquitectura, código fuente y decisiones de ingeniería.

  • Proyecto open source NubeHerramientas

    Azure Blueprint

    Reto
    Los diagramas de recursos de Azure, las dependencias de Bicep y los grafos de CI/CD suelen enseñarse por separado, dificultando el paso de la arquitectura al despliegue.
    Solución
    Un curso interactivo con lecciones SVG animadas, un depurador visual de YAML en el navegador y ejercicios guiados de pipelines.
    Resultado
    26 lecciones en 7 módulos, 10 ejercicios prácticos y 8 hojas de referencia. Compatible con GitHub Actions, Azure DevOps y GitLab CI sin backend.

    Tecnologías:

    • JavaScript
    • SVG
    • HTML / CSS
    • Bicep
    • Azure CLI
    • GitHub Actions
    • Azure DevOps
    • GitLab CI
    Leer el caso de ingeniería — Azure Blueprint

    Mi rol

    Creador y mantenedor. Diseñé lecciones interactivas de arquitectura y herramientas de depuración de pipelines.

    Arquitectura

    Una aplicación estática en JavaScript conecta un motor de lecciones, diagramas SVG y un grafo de dependencias YAML. La validación y simulación de pipelines se ejecutan en el navegador, sin backend.

    Azure e infraestructura

    Los ejemplos Bicep definen App Service, Storage, identidad administrada, Application Insights y Log Analytics. Muestran dependencias, HTTPS y telemetría; no incluyen código de aplicación ni asignaciones de roles de almacenamiento.

    CI/CD

    Los ejemplos de GitHub Actions, Azure DevOps y GitLab CI comparten un flujo de validación → what-if → aprobación → despliegue → comprobación, con identidad federada. El curso utiliza un workflow separado de validación y publicación en GitHub Pages.

    Decisiones y resultados

    El depurador detecta ciclos y dependencias ausentes y simula trabajos paralelos, aprobaciones y propagación de fallos. La ejecución en el navegador evita enviar el YAML a un servidor. El simulador simplifica el comportamiento de los proveedores y considera verdaderas las condiciones; no ejecuta despliegues.

    GitHub — Azure Blueprint (se abre en una pestaña nueva)
  • Proyecto open source IANube

    Vectaris

    Reto
    Los equipos que ejecutan LLM y agentes en producción no tienen una vista única de uso, latencia, costo y salud de los agentes.
    Solución
    Una capa de observabilidad unificada que agrega telemetría de endpoints LLM, runtimes de agentes y API de costos en la nube, con un proxy LLM que captura tokens y latencia.
    Resultado
    Latencia P50/P95/P99 por modelo, atribución de costos por equipo, reglas de alerta en YAML y autenticación OIDC, desplegable en AKS con Helm y Bicep.

    Tecnologías:

    • Python
    • FastAPI
    • React
    • OpenTelemetry
    • GraphQL
    • Kubernetes
    • Bicep
    GitHub — Vectaris (se abre en una pestaña nueva)
  • Proyecto open source Seguridad

    PQE — Post-Quantum Encryption

    Reto
    Las computadoras cuánticas romperán RSA y la criptografía de curva elíptica. Las organizaciones necesitan una ruta concreta y comprobable hacia los estándares poscuánticos del NIST.
    Solución
    Una solución de referencia en .NET 10 que implementa ML-KEM (FIPS 203), ML-DSA (FIPS 204) y SLH-DSA (FIPS 205), además de patrones de migración híbrida clásica + PQC.
    Resultado
    Solución con arquitectura limpia, API en ASP.NET Core, instrumentación OpenTelemetry, pruebas unitarias, de integración y de seguridad, y benchmarks con BenchmarkDotNet.

    Tecnologías:

    • C#
    • .NET 10
    • ASP.NET Core
    • OpenTelemetry
    • BenchmarkDotNet
    GitHub — PQE — Post-Quantum Encryption (se abre en una pestaña nueva)
  • Proyecto open source Nube

    Hyperscale Observability Platform

    Reto
    Diagnosticar pérdida de paquetes en una red definida por software global exige correlacionar volúmenes enormes de telemetría casi en tiempo real.
    Solución
    Un pipeline OpenTelemetry en Azure —Event Hubs, AKS con KEDA y Azure Data Explorer— con atribución de pérdidas, análisis de grafos causales y una API de diagnóstico.
    Resultado
    Diseñado para una meta de más de 1,000 millones de eventos de telemetría por minuto, con IaC completo en Bicep e identidad zero-trust (Managed Identity, federación OIDC).

    Tecnologías:

    • Python
    • OpenTelemetry
    • Azure Event Hubs
    • AKS
    • Azure Data Explorer
    • Bicep
    • Grafana
    GitHub — Hyperscale Observability Platform (se abre en una pestaña nueva)
  • Proyecto open source IAHerramientas

    AI Orchestrator

    Reto
    Los flujos de contenido y publicación tienen muchos pasos repetitivos que los equipos quieren automatizar sin enviar datos a servicios SaaS de terceros.
    Solución
    Un pipeline multiagente autoalojado en n8n y Docker que indexa un espacio de trabajo, cura contenido, genera publicaciones, ejecuta control de calidad y publica un índice.
    Resultado
    Funciona totalmente aislado de internet, con una rama opcional de LLM local (compatible con Ollama) que se activa por configuración.

    Tecnologías:

    • n8n
    • Docker
    • JavaScript
    • PowerShell
    • Ollama
    GitHub — AI Orchestrator (se abre en una pestaña nueva)
  • Proyecto open source Herramientas

    Gateorix

    Reto
    Las aplicaciones de escritorio obligan a elegir entre interfaces web modernas y acceso nativo al sistema operativo en el lenguaje de backend preferido del equipo.
    Solución
    Un framework en Tauri/Rust que combina frontends web con API nativas y permite escribir la lógica de backend en Python, Go, C#, Rust y otros lenguajes.
    Resultado
    CLI publicado en npm, plugins nativos protegidos por permisos y una extensión de VS Code para validar la configuración.

    Tecnologías:

    • Rust
    • Tauri
    • TypeScript
    • Python
    • Go
    • .NET

Sobre mí

Ingeniería: de la arquitectura a la implementación

Desarrollo software desde 2001 para sistemas de salud, finanzas y empresas en Puerto Rico. En Microsoft desarrollé y operé servicios de firma de código y publicación de software. Mi trabajo actual abarca arquitectura cloud, ingeniería backend, entrega segura e IA aplicada.

Mi formación en electrónica guía mi enfoque del software: comprender el sistema completo, hacer explícitas las dependencias y diseñar para los fallos. Valoro los sistemas observables, la infraestructura reproducible y la documentación que permite a otros ingenieros entender las decisiones. Este portafolio reúne herramientas open source e implementaciones de referencia que muestran ese enfoque.
